---
name: handoff
description: Capture a requested interactive session boundary in the existing work owner and provide the next fresh-session prompt with model and effort guidance.
---

Read [the work-record policy](../../reference/work-records.md), [the model reference](../../reference/models.md), and [session prompt requirements](../plan-sessions/SKILL.md). This captures a human-led session boundary.

Inspect the current work owner, changes, branch, commit and uncommitted state. Compare the actual outcome with acceptance criteria. Explain what was accomplished, what the evidence establishes, and what must happen next. Distinguish validated work, implementation awaiting verification, and blocked or unfinished work. Summarize validation results and limits, unresolved decisions and the next concrete step; link detailed evidence in appropriate existing docs or CI/PR records. Include commands only when needed to reproduce a task-specific result. A passing subset or skipped check does not establish full completion.

Rewrite the existing owner as the current actionable plan using the work-record policy's reconciliation and closeout procedures; remove superseded instructions instead of prepending another update. They govern contributing sources, PR and integration evidence, parent coordination, dependent instructions, verification of the continuation source, publication authority and read-back. Record express user overrides and any remaining delivery gates. Use comments only for significant decisions or new evidence, not prior-body archives or routine progress logs. Do not create a document for a routine update. If publication is unavailable, prepare temporary ready-to-post updates and identify what remains unpublished. With no owner, use a temporary handoff unless a durable record is requested.

For the next ready session, provide one compact, self-contained, copyable prompt following `plan-sessions`. Name the project, verified continuation source, owner and bounded outcome; link the authoritative context, prerequisites and completion criteria. Reference shared procedures and include task-specific exceptions and consequential constraints. Put the specific model, supported effort, harness and task-based rationale outside the prompt, following the model reference's availability, efficiency and escalation rules. With a parent, keep the prompt there and link to it from the child and handoff response. Name the parent in the prompt and require reconciliation and read-back under the work-record policy before finishing. Replace the old prompt; if no session is ready, remove it and state activation conditions for blocked or deferred work. At closure, leave the accepted result or deferred/superseded disposition, essential evidence, material limits and owner of unfinished work, without an obsolete continuation prompt. Apply the policy's fresh-reader review before publishing.

Adapted in part from Matt Pocock's handoff; see [attribution](../../reference/upstream.md).

When relevant personal facts or preferences affect this task, use [private context](../../reference/private-context.md). Load only the needed topics; ask about consequential unknowns and save confirmed updates through its tool. Keep personalized profiles and reports private.
