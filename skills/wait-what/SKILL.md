name: wait-what
description: Re-explain the last message when the user says wait-what or says the explanation did not land.
---

Pause and reconsider the point that did not land. Look for an unstated assumption, missing context or a connection the earlier explanation left the reader to make. Explain the point afresh using the shared working agreements: establish where we are, make the key idea concrete, and connect it to what the user needs to understand or do next. A useful example can replace an abstraction; simply shortening or repeating the earlier wording may leave the same misunderstanding. If a question is needed, ask one and wait.

Adapted from Matt Pocock's wait-what: retains the context reset, with everyday language and project vocabulary guidance in the shared agreements. See [attribution](../../reference/upstream.md).

When relevant personal facts or preferences affect this task, use [private context](../../reference/private-context.md). Load only the needed topics; ask about consequential unknowns and save confirmed updates through its tool. Keep personalized profiles and reports private.
