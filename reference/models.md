# Choosing models for work sessions

Choose a model, supported effort setting, and client for each session from the task's needs and the user's available options. Read relevant [private context](private-context.md) first: access, provider order, rotation preferences, task-specific choices, and dated local launch evidence belong there.

Public documentation describes capabilities; a local client listing describes launch settings; neither establishes account access or successful inference. Confirm the intended client, model identifier, effort controls, tool availability, and usable context. Keep historical evidence dated. If a needed fact is unknown, ask one question at a time rather than inventing a model/effort pair.

Match the recommendation to the session:

- Light, well-defined work: favor an available economical option with easy verification.
- Ordinary implementation and planning: use the user's preferred general model at an appropriate effort.
- Investigation: account for unresolved interactions and available checks.
- Reasoning escalation: explain the concrete risk or observed difficulty that warrants more usage.
- Visual or prose work: consider capabilities relevant to the actual material.

Measure efficiency by total time and usage to an accepted result, including retries and human review. Respect explicit model choices. Do not assume one provider is available or preferred; use the private profile's provider order and rotation preferences. Recommendations do not authorize provider switching, paid inference, or credential access.

Put the selected model, supported effort, client, and rationale outside a copyable session prompt. Shared records may state that selection without reproducing the private access inventory or hardware facts behind it.

For fresh comparisons, run the private model-guidance tool described in [refreshing guidance](../docs/model-guidance.md). Its dated output stays outside repositories. Benchmark settings are not launch identifiers; API prices do not measure subscription allowances. Local weight estimates are preliminary memory checks, not proof of runtime speed or context capacity.

Use official provider documentation for capabilities and launch controls, and public comparison evidence such as [Artificial Analysis](https://artificialanalysis.ai/models) for benchmark context. Verify availability in the user's environment. Keep generated comparisons, local cache observations, and personal choices in private context.
